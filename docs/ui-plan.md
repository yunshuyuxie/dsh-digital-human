# 浮窗 UI 调整计划

依据：`dist/pet-m3.png`、`dist/pet-packaged.png`、`dist/pet-wiz2.png` 等实际截图，以及使用过程中暴露的问题。
每条都写明**现象 → 原因 → 方案 → 验收**，便于逐条实施与确认。

## 优先级 P0：先修「信息看不到」

### 1. 模型选择行把输入框挤出可视区

- **现象**：加入模型选择后，composer（输入框 + 发送/取消）在 360×560 的窗口里落到可视区之外，需要滚动才能看到。
- **原因**：纵向预算被吃满——化身 200 + 状态行 + 会话列表（7 行）+ 活动区 + 模型行 + 输入区 + 页脚 > 560。
- **方案**：把模型选择从 composer 移到**会话行右侧**（一个窄的下拉，或在选中会话的标题行显示 `provider/model` 并可点选），composer 只保留输入 + 发送 + 取消。
- **验收**：选中任一会话后，输入框无需滚动即可见；模型切换仍可用。

### 2. 活动区与列表的纵向分配是固定的，不随内容伸缩

- **现象**：会话少时活动区仍占固定高度；会话多时列表被挤压。
- **方案**：改为 `flex` 分配 + `min-height`：会话列表最多显示 N 行后滚动，活动区占剩余空间。
- **验收**：3 个会话与 12 个会话两种情况下，输入框位置都不变。

## 优先级 P1：让化身更像「桌面宠物」

### 3. 只显示化身的紧凑形态（最初的桌面宠物设想）

- **现象**：现在必须常驻一个 360×560 的面板，占地偏大。
- **方案**：两档形态——**紧凑**（约 200×220，仅化身 + 状态光环，点击展开）与**标准**（现面板）；托盘菜单可切换，并记住选择。
- **验收**：紧凑形态下能看到七态切换与"待确认"徽标；点击化身展开为标准形态。

### 4. 透明窗口的背景内容会透出

- **现象**：面板 0.92 不透明，背后 Web GUI 的文字会隐约透出（截图中出现过来自背后的「正在思考…」，我排查确认不是 App 渲染的）。
- **方案**：给面板加「不透明度」设置（0.85 / 0.92 / 1.0），默认 0.92 保持不变；或提供"纯色模式"。
- **验收**：切到 1.0 时背后内容完全不可见。

## 优先级 P2：可读性与操作效率

### 5. 会话列表行距偏松

- **现象**：7 行就占满列表区，标题还被截断（如 `Implement FOUR support modules of`）。
- **方案**：收紧行高（约 32→26px）与字号；标题两行截断改为单行 + `title` 悬停；运行中/出错用左侧色条而非整行描边。
- **验收**：同高度可见会话数提升约 40%；悬停可看全标题。

### 6. 断连原因的长文案被截断

- **现象**：`正在寻找端点文件… — 未找到端点文件 —— dsh 是…`（已有 `title` 兜底）。
- **方案**：断连时状态行改为**两行**（第一行状态、第二行原因灰字），或状态图标 + 悬停详情。
- **验收**：360px 宽度下断连原因完整可读。

### 7. 活动区只看单个会话

- **现象**：默认只显示选中会话的活动，容易错过别的会话出错。
- **方案**：增加「全部会话」聚合视图，**待确认 / 出错 / 运行中**优先置顶，每行带会话前缀。
- **验收**：不选中任何会话时也能看到全局动态与错误。

### 8. 键盘与快捷键

- **方案**：`Enter` 发送（`Shift+Enter` 换行）、`Esc` 隐藏浮窗、`Ctrl+1..9` 选会话。
- **验收**：纯键盘可完成"选会话 → 输入 → 发送 → 批准/拒绝"。

## 优先级 P3：多窗口形态（最初的第三个方案）

### 9. 化身浮窗 + 独立监控面板

- **方案**：把现在一个窗口拆成两个——角落小化身（常驻、可置顶）+ 按需打开的面板（可最大化、可多屏）。
- **前置**：P1-3 的紧凑形态做完之后，这一步基本是复用。
- **验收**：两个窗口共享同一份快照，任一窗口批准后另一窗口的卡片同步消失。

## 实施建议顺序

1. **P0-1、P0-2**（一次性重构纵向布局，解决"看不到输入框"）
2. **P2-5、P2-6**（列表与状态行的可读性，改动小、收益直观）
3. **P1-3、P1-4**（紧凑形态 + 不透明度，让它真的像桌面宠物）
4. **P2-7、P2-8**（聚合活动流与快捷键）
5. **P3-9**（多窗口）

## 需要你先定的两件事

- **默认形态**：紧凑（省地方）还是标准（信息多）？我倾向**首次为紧凑**，因为它更符合"桌面宠物"的预期，且点击即展开。
- **窗口尺寸是否可调**：现在固定 360×560 且 `resizable: false`。若要允许用户拉伸，需要重新考虑列表/活动区的伸缩规则（P0-2 正好是前提）。
